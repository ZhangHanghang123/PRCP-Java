一功能概述

1.1 定位

结果驾驶舱是组合反算链路的最终交付视图。用户在「测算方案」页签配置好账户册方案与目标约束、 触发引擎完成寻优后，本页把一次运行的全部产出聚合到单一视图中，用于回答三类问题：

  • 跑出来了吗 —— 目标达成情况、监管指标是否达标（目标达成进度区 + 8 张 KPI 卡）
  • 过程怎么样 —— 指标沿 24 个月预测期的演进轨迹、评分档位（趋势图 + 雷达图）
  • 钱去哪了 —— 资产负债表结构与变动（节点排行、大类分布、余额分布、走势）
入口与承载

路由 /prcp-java/reverse（「测算方案」菜单）→ 第 3 个页签「测算结果」→ 组件 src/views/reverse/components/DashboardPanels.vue。 本页为纯只读展示页，不写库；仅「导出结果」按钮产生一个下载动作。

1.2 与原系统的关系

本页对位 Python 原系统 frontend/src/pages/ReverseDashboard.tsx，在 Java 化过程中按原系统语义重建了 5 个区块， 并补充了原系统缺失的阈值达标徽标、趋势图指标切换、雷达图多指标图例三项交互。 口径差异详见 第九章。

查询条件的三个口径注意点
  • 「余额口径」不参与服务端查询——它是纯前端开关，在「基准日当前余额」与「当月预测余额」两套已返回数据间切换；因此切换时不会重新请求。
  • 「预测月份」只改当前期，不改基期——KPI 卡下方的「基期 …」行恒为 M1（date_offset=1）。当选择 M1 时，基期行与当前值相同，变化量为 0。
  • 「余额口径 = 基准日」时，分布图不随预测月份变化——基准日是方案起点、固定不变。页面已在环形图上方显式给出该提示。

6.1 监管阈值（常量）

指标阈值方向超标级别

6.2 Run 解析与「断裂回退」

历史数据中 prcp_reverse_run.id 与 prcp_data_reverse.run_id 存在关联断裂 （引擎写入的 run_id 与事后登记的 run 记录 id 不一致）。若只取「最新 SUCCESS」，按 (scheme_code, run_id) 查月度数据将得到 0 行 → 整页空白。因此设计了三级解析：

# ① 显式指定 run_id → 直接采用，不校验、不回退 if (runId != null) return runId; # ② 该方案下最新 SUCCESS run，且确认它在 prcp_data_reverse 中确有数据 candidate = SELECT id FROM prcp_reverse_run WHERE scheme_id = ? AND status = 'SUCCESS' AND is_deleted = 0 ORDER BY id DESC LIMIT 1 if (COUNT(prcp_data_reverse WHERE scheme_code = ? AND run_id = candidate) > 0) return candidate; # ③ 断裂回退：该 scheme_code 下实际有数据的 MAX(run_id) rid = SELECT MAX(run_id) FROM prcp_data_reverse WHERE scheme_code = ? AND is_deleted = 0 if (rid != null) return rid; # ④ 都取不到 throw BizException.notFound("该方案无 SUCCESS 运行记录") → code 404

6.3 指标均值（metric_avg）

口径定义（需在验收时重点核对）

节点级指标全样本等权均值：分母为「在该指标上取值非 null 的节点数」， 不做末级过滤、不做余额加权，4 位小数 HALF_UP。 同一算法同时用于当前期 kpi.metric_avg、基期 kpi_base.metric_avg、 以及目标达成行的 current_value / m12_value。

vals = [ mv[m] for node in ALL_NODES if (mv := metricMap[node.node_code]) and mv[m] != null ] metric_avg[m] = SUM(vals) / COUNT(vals) // scale 4, HALF_UP

6.4 贷款加权平均利率（loan_weighted_rate）

# 节点范围: 5 个 L4 前缀白名单 (S01010101 ~ S01010105) # L3 父节点 S010101000000 因前缀不匹配而自然被排除 # 剔除近零余额 |bal| < 0.01 loanNum += bal * rate // 带符号余额 loanDen += bal // 带符号余额 loan_weighted_rate = (loanDen > 0) ? loanNum / loanDen : null // scale 6

库中 weighted_rate 为小数（0.038855 = 3.89%），前端展示时须 ×100。 本页由 loanRatePct() 统一换算，表格与 KPI 卡共用。

6.6 末级节点判定

场景判定方式
KPI 余额汇总（sumByCat）仅 path 前缀推断：节点 N 是父节点 ⇔ 存在 M 使 M.path 以 N.path + "/" 开头

说明

6.7 目标完成率（completion）

# 量纲保护: |actual / |target|| 不在 [0.001, 1000] → 返回 null (不可比) GE: actual * 100 / target // 分母用带符号 target LE: (actual == 0) ? null : target * 100 / actual // 分母用带符号 actual EQ: (1 - |actual - target| / |target|) * 100 其他 constraint_type → null
字段口径
current_rate当前期实际值对目标值的完成率，单位 %，2 位小数
m12_rateM12 期实际值对目标值的完成率；M12 实际值取 prcp_metric_coefficient 在 M12 数据日期的值
achievedGE → actual ≥ target；LE → actual ≤ target；其他 → |actual − target| < 1e-9

7.1 8 张 KPI 卡

卡片主值副标题基期对比行达标徽标
资产余额金额（亿/万亿）—基期 + 变化量—

LCR 流动性覆盖率百分数阈值 ≥ 100%基期 + 变化量未达标
NSFR 净稳定资金百分数阈值 ≥ 100%基期 + 变化量未达标

KPI 卡设计约定
  • 主值旁不显示涨跌箭头——方向信息由基期对比行的「±变化量」承载，避免同一张卡出现两个方向指示。
  • 达标徽标替代原系统的红色箭头：ROE/CET1/LCR/NSFR 低于下限标「未达标」（橙），△EVE 超过绝对值上限标「超标」（红）；达标则不显示徽标。
  • 变化量颜色：越高越好类指标涨绿跌红；越低越好类（贷款利率、△EVE）跌绿涨红；规模类（资产、负债）涨蓝跌橙。
  • 变化量四舍五入为 0 时抹掉负号，避免出现「−0.00」这类无意义显示。
  • 金额采用紧凑格式：≥1 万亿显示「X.XX 万亿」，≥1 亿显示「X.X 亿」，去掉千分位与「元」字。

项内容
端点GET /reverse-dashboard/balance-export?scheme_code=&run_id=&date_offset=
参数均可选；不传时取最新方案与该方案最新 SUCCESS Run；date_offset 决定「当前期指标与评分」导出哪一期，缺省取该 Run 最大 offset

格式5 个 Sheet，数值格式 #,##0.00
Sheet内容结构
① 账户册结构 逐节点逐月余额明细 列：节点编码 / 节点名称 / 层级 / 大类 / 末级节点 / 各月余额
非末级行以上卷值填充（子树内末级节点之和）并加浅蓝底
② 按层级汇总 大类 × 层级的节点数与逐月汇总 列：大类 / 层级 / 节点数 / 末级节点数 / 各月汇总
末行为「末级合计」
③ 末级节点大类汇总 5 大类逐月金额 列：大类 / 各月金额，末行为「合计」
④ 当前期指标与评分 5 个监管指标的当前期值、基期值、变化量、阈值、达标状态、评分与档位 列：指标 / 指标编码 / 单位 / 当前期值 / 基期值 / 变化量 / 阈值 / 达标状态 / 评分 / 评分档位 / 当前期数据日期
达标状态绿字=达标 / 红字=未达标；指标为 ROE / CET1 / LCR / NSFR / △EVE
⑤ 口径说明 13 项元信息 组合方案 / Run ID / 账户册方案 / 基准日 / 预测期 / 月份区间 / 节点数 / 有预测值节点数 / 数据来源 / 导出时间 / 余额口径 / 单位说明 / 当前期指标口径
「当前期指标与评分」的口径（与页面 KPI 卡严格一致）
  • 指标值 —— 该期全部有值节点的等权平均（分母 = 该指标有值节点数；不做末级过滤、不做余额加权），4 位小数 HALF_UP；与页面 kpi.metric_avg 同源同算法。
  • 基期值 —— 取 date_offset=1 对应数据日期，恒为 M1，不随所选月份变化。
  • 评分 —— prcp_kpi_value.score（0–500 分制），绑定基准日，不随所选月份变化；档位由 prcp_kpi_score_segment 按该指标值命中区间取得。
  • 阈值 —— 与页面同一份常量：ROE ≥ 11% / CET1 ≥ 8.5% / LCR ≥ 100% / NSFR ≥ 100% / △EVE |x| ≤ 5 亿。
导出口径与页面的差异（使用前需知悉）
  • 节点范围不同：Sheet ①②③ 仅覆盖方案自身关联的那一套账户册，而页面覆盖全部 COA 方案；但 Sheet ④「当前期指标与评分」的指标值与页面同范围（全部 COA 的全部节点）。
  • 余额口径不同：导出对父节点做层级上卷（子树末级之和），页面只取末级节点自身值。
  • Sheet ② 的层级行之间存在父子重叠，跨行相加会重复计数；仅末行「末级合计」是干净口径。

九口径差异与风险清单

以下 20 项为源码审阅与实测比对中识别出的口径差异或实现风险，按影响程度分级，供后续迭代排期参考。

#级别位置问题影响
1高category_distribution.by_balance 数据来自 prcp_data_reverse，却标注 balance_source="prcp_data_basic"；balance_date 标基准日但值取当前期；且未做末级过滤（父子重复计数） 大类分布口径错误风险
2高sumByCat vs isLeafFlag 前者仅用 path 前缀推断末级，后者优先取 prcp_data_basic.is_leaf KPI 余额与分布图的末级集合可能不一致
3高options.default.date_offset 取 MAX(date_offset)（通常 24），而 /snapshot 缺省为 1 前端若直接采用默认值会落到 M24 而非 M1
4高目标达成进度条 进度条宽度用完成率（99.28% 即 99% 宽），颜色却按 achieved 标红 出现「红色满条 + 文字标未达成」的视觉矛盾
5中options / balance-export 默认 Run 均只取最新 SUCCESS，不走断裂回退逻辑 可能指向无数据的 Run
6中snapshot 空响应 节点为空或无月度数据时返回 {code:0, data:{}}，无任何报错 前端需处理「字段全缺」情形
7中kpi_scores 绑定基准日，不随所选月份变化 雷达图评分不反映所选月份
8中trend 指标 fallback 链 与 kpi.metric_avg 所用链不同（含 COA 档、不限日期） 同一响应内 KPI 均值与趋势末月值可能来自不同数据源
9中balance-trend 错误码 方案不存在时 queryForMap 抛异常 → HTTP 500；snapshot 为 404 错误码不一致
10中导出 Sheet ② 层级行含父子重叠，跨行相加会重复计数 报表二次汇总出错风险
11中导出 Sheet ⑤ 单位说明 称「各层级互不重叠」，与 Sheet ② 实际不符 文案与实现冲突
12中导出文件名 用原始入参而非解析后的方案 / Run 空参时文件名缺方案段
13低completion 的 GE 分母 用带符号 target，负目标 → 完成率为负 负目标场景展示异常
14低targets[].achieved 的 EQ 用精确相等（1e-9）判定，与 current_rate 的比例公式语义不一致 EQ 目标几乎恒为未达成
15低risk_alert_total 是有告警的节点数，非告警条目总数 统计口径误解风险
16低balance-trend monthByNode 按 node_code 建键而非 coa_node_id 跨 COA 同 code 会互相覆盖
17低鉴权 JWT 过滤器只解析不拦截，端点无 @PreAuthorize 实际可匿名访问
18低多处 Javadoc options(algorithms)、runs(started_at)、dates(纯数字数组)、导出文件名描述均与实现不符 文档误导
19低资产 / 负债 KPI 卡 缺口径说明行，其余 6 张有「阈值…」或说明 两行卡片结构不齐
20低测试数据特征 ZX_COA 为等差构造数据（每期 +0.04），ROE/CET1/LCR 变化量同为 +0.92 对外演示前建议换真实 Run
