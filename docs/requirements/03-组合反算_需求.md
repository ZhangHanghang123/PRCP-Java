## 一、业务背景

### 1.1 业务问题

传统的资产配置是**自上而下**：先定预算，再分解到各业务条线。但在**利率风险**（IRRBB）、**资本充足率**约束下，常常反过来：

> 给定指标约束（如 CET1 ≥ 8.5%、ROE ≥ 11%、LCR ≥ 100%），倒推**需要多少资产/负债配置**才能达标？

这就是 **反算（Reverse Calculation）** 的核心场景。

银行的实际痛点：
1. **监管达标压力大**：指标约束多（5+ 个监管指标），手工调参效率低
2. **多目标冲突**：高 ROE 与低 LCR 难以兼顾，需要**算法寻优**
3. **路径依赖**：24 月预测窗口里每月资产配置需平滑（不允许断崖式调整）
4. **结果难解释**：方案执行后，业务人员难以理解**为什么是这个配置**

### 1.2 业务目标

建立**组合反算驾驶舱**：
1. 配置**反算方案**（关联账户册 + 计量模型）
2. 设置**目标约束**（例：未来 24 月 CET1 ≥ 8.5%）
3. **异步运行**反算算法（DNN/蚁群/NS 求解）
4. 查看**结果驾驶舱**（KPI / 趋势 / 雷达图 / Top10 节点 / 热力图）
5. 支持**方案对比**（DNN 方案 vs 蚁群方案）

## 三、功能清单

### 3.1 反算方案（Scheme）

| 字段 | 类型 | 必填 | 备注 |
|---|---|---|---|
| scheme_code | String | 是 | 唯一编码（如 `REV_DNN_REG`）|
| scheme_name | String | 是 | 显示名称 |
| coa_scheme_id | Long | 是 | 关联账户册方案 |
| model_id | Long | 是 | 关联计量模型 |
| algorithm | String | 是 | NONLINEAR_SOLVER / DNN_NEURAL_NETWORK / ANT_COLONY |
| horizon_months | Int | 是 | 预测窗口（如 12 / 24）|
| base_data_date | Date | 是 | 基期（如 2025-12-01）|
| status | String | 否 | ACTIVE / INACTIVE |

### 3.2 反算目标（Targets）

| 字段 | 类型 | 必填 | 备注 |
|---|---|---|---|
| scheme_id | Long | 是 | 外键 |
| kpi_id | Long | 是 | 关联 KPI 定义 |
| target_value | Decimal | 是 | 目标值（如 8.5 表示 8.5%）|
| comparison_type | String | 是 | GTE / LTE / EQ |
| weight | Decimal | 否 | 加权（多目标时使用）|

### 3.3 反算运行（Runs）

| 字段 | 类型 | 备注 |
|---|---|---|
| scheme_id | Long | 外键 |
| run_no | Int | run 序号 |
| run_status | String | PENDING / RUNNING / SUCCESS / FAILED / CANCELLED |
| start_time | Datetime | — |
| end_time | Datetime | — |
| elapsed_ms | Long | 耗时 |

### 3.4 测算结果驾驶舱（Dashboard）

包含 **6 大模块**（详见设计文档）：
- **筛选条**：方案 / Run / 月份下拉
- **KPI 区**：8 个 KPI 卡 + 5 维雷达图
- **5 指标 24 月趋势**：折线图
- **大类分布**：环形饼图 + 柱状图
- **节点 × 指标 热力图**：heatmap
- **Top 10 节点**：按当前余额绝对值排序

## 五、验收标准

### 5.1 算法对齐

| 指标 | 标准 |
|---|---|
| 新业务模拟（NS 求解）| Java run vs Python run 当前余额/平均余额/加权利率 偏差 < 1e-6 |
| 反算（DNN/蚁群）| 接入 prcp_metric_coefficient 数据，验证 trend ≥ 23 个有效节点 |

### 5.2 驾驶舱呈现

| 指标 | 标准 |
|---|---|
| KPI 卡 | 资产/贷款加权 指标与 Python 源系统偏差 < 0.01 |
| 雷达图 | 5 维评分（ROE/CET1/LCR/NSFR/△EVE）正确渲染 |
| 趋势图 | 24 月折线，含 5 个 REG 指标 |
| 热力图 | 节点 × 指标 真 heatmap（visualMap 色阶） |

## 六、约束与限制

- **算法以 Mock 为主**：当前 Java 版接 §5算法本身可能仍是 Mock，关键在数据接入正确
- **结果存储**：每次 run 24 月 × N 节点，存储 `prcp_data_reverse` 表
- **驾驶舱数据**：从 `prcp_data_reverse + prcp_metric_coefficient + prcp_kpi_value` 多表聚合

## 七、不在本期范围

- 实时在线反算（仅离线批量）
- 算法可视化编排（用不同算法只需切换 model_id）
- 跨方案合并对比
