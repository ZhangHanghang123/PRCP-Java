## 三、关键设计实现

### 3.1 异步训练实现（Java 线程池）

```java
@Service
public class ModelService {
    private final ExecutorService trainPool = Executors.newFixedThreadPool(4);

    public R<Map<String, Object>> startTrain(Long modelId, Map<String, Object> body) {
        // 1. 创建 prcp_model_train 记录（PENDING）
        // 2. 异步提交任务
        trainPool.submit(() -> {
            // 3.1 状态改为 RUNNING，写入日志
            // 3.2 模拟 N 次 epoch（默认 100），每 500ms 写一条日志
            // 3.3 计算 loss / accuracy 模拟值
            // 3.4 状态改为 SUCCESS，写入 final_loss / final_accuracy
        });
    }
}
```

### 3.2 增量日志协议

```
GET /model/{mid}/logs?train_id=42&last_id=10
```

返回 `id > last_id` 的日志 + `next_id` 供前端下次拉取：
```json
{
  "logs": [
    {"id": 11, "ts": "...", "level": "INFO", "message": "..."},
    {"id": 12, "ts": "...", "level": "INFO", "message": "..."}
  ],
  "next_id": 12,
  "status": "RUNNING"
}
```

### 3.3 版本复制（base_version_id）

```sql
INSERT INTO prcp_model_version (..., version_code, base_version_id, ...)
SELECT ..., 'v2.0.0', id, ... FROM prcp_model_version WHERE id = ?;

INSERT INTO prcp_model_param (version_id, param_key, param_value, value_type)
SELECT ?, param_key, param_value, value_type FROM prcp_model_param WHERE version_id = ?;
```

## 四、踩坑与修复

### 4.1 模型/版本创建后未触发刷新

**问题**：新建模型后切换到版本 tab，未自动加载版本列表。

**修复**：切换 tab 时手动 `loadVersions()` 一次。

### 4.2 训练日志过频查询导致 DB 压力

**问题**：前端默认每 2s 拉一次日志，DB 锁竞争。

**修复**：
1. 服务端按 last_id 过滤 + LIMIT 100 限制单次返回
2. 前端按训练状态动态调频率：RUNNING 时 5s，成功/失败时 30s

### 4.3 取消训练无响应

**问题**：调用 `/model/train/cancel` 但线程不响应（sleep 不响应中断）。

**修复**：训练循环检测 `Thread.interrupted()`：
```java
while (epoch < maxEpoch) {
    if (Thread.currentThread().isInterrupted()) {
        // 写状态为 CANCELLED
        return;
    }
    // 训练一个 epoch
    Thread.sleep(500);
}
```

### 4.4 训练结果未关联主表

**问题**：训练成功只写 `prcp_model_train.final_loss`，但前端期望 GET `/results` 返回关联 `prcp_model_version` 的所有训练。

**修复**：service 层 JOIN `prcp_model_version` + `prcp_model` 返回完整结构。
