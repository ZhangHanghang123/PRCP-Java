# 模型管理（Model）— 设计方案

| 版本 | 日期 | 作者 |
|---|---|---|
| v1.0 | 2026-10-08 | 主程 |

## 一、整体架构

```
前端 Vue3 (src/views/model/Index.vue)
   ↓ axios
后端 Spring Boot (prcp-business/com/prcp/business/model/)
   ├── controller/ModelController.java
   ├── service/ModelService.java
   ├── entity/{Model, ModelVersion, ModelParam, ModelTrain}.java
   └── mapper/{ModelMapper, ModelVersionMapper, ModelParamMapper, ModelTrainMapper}.java
   ↓ Java 线程池模拟
异步训练任务（ModelTrainEntity.trackStatus）
   ↓
训练日志（prcp_model_train.log 字段，clob 或 text）
   ↓
训练结果（loss / accuracy / duration）
```

### 4.2 训练协议

#### 启动训练

`POST /model/{mid}/train`
```json
{
  "version_id": 1,
  "param_overrides": [
    {"key": "learning_rate", "value": "0.0001"}
  ],
  "use_existing_param": true
}
```

响应：
```json
{
  "code": 0,
  "data": {
    "train_id": 42,
    "model_id": 1,
    "version_id": 1,
    "status": "PENDING",
    "message": "训练任务已入队"
  }
}
```

#### 增量日志

`GET /model/{mid}/logs?train_id=42&last_id=0`

返回新日志（last_id 增量拉取）：
```json
{
  "logs": [
    {"id": 1, "ts": "...", "level": "INFO", "message": "Epoch 1/1000 loss=0.32"},
    {"id": 2, "ts": "...", "level": "INFO", "message": "Epoch 2/1000 loss=0.28"}
  ],
  "next_id": 2,
  "status": "RUNNING"
}
```

## 五、UI 设计

### 5.1 页面结构

```
┌─────────────────────────────────────────┐
│  模型管理                            │
│  [模型管理][版本管理]                │ ← 2 tabs
├─────────────────────────────────────────┤
│  [查询][重置][+ 新建模型]            │
│  ┌───────────────────────────────────┐ │
│  │  # / 编码 / 名称 / 算法 / 状态 / 操作│ │
│  └───────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

### 5.2 关键交互

- **新建模型**：弹窗，算法下拉（来自 `/model/algorithms`）
- **新建版本**：弹窗，可选「复制现有版本」自动带入超参
- **启动训练**：异步不阻塞，跳转运行记录 tab 实时拉日志
- **取消训练**：运行中按钮变 `取消` 点击 POST `/train/cancel`

### 5.3 视觉规范

- 算法用**蓝色 tag** 标识（Neural DAG / Ant Colony / NS Solver）
- 训练状态：
  - PENDING → 🟡 黄
  - RUNNING → 🔵 蓝（loading 动画）
  - SUCCESS → 🟢 绿
  - FAILED → 🔴 红
  - CANCELLED → ⚫ 灰

## 六、关键设计决策

### 6.1 异步训练用 **Java 线程池**（而非阻塞调用）

**理由**：
- 训练可能 5-10 分钟，HTTP 超时风险高
- 用户体验：实时日志 + 可取消

### 6.2 训练日志用 **增量拉取**（last_id 游标）

**理由**：
- 不每次返回全量日志
- 前端只需追加渲染

### 6.3 超参数 key/value 用 **JSON 而非字段**

**理由**：
- 灵活：算法差异不需要改表结构
- 简单：v1 加 1 个超参 ≠ 无需 ALTER TABLE

## 七、与其他模块的关系

- **组合反算**：模型的 `algorithm` 字段决定反算用哪种算法
- **指标管理**：间接通过反算结果 → KPI
