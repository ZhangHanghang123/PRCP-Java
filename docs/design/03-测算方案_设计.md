### 1.2 🆕 引擎拆服务器 (核心架构变化)

**v1 进程内**:
```
Vue → 主服务 ReverseService.startRun() → CompletableFuture.runAsync(executeReverse, EXEC)
                                       → 进程内 solve() (HEURISTIC)
```

**v2 HTTP 异步**:
```
Vue → 主服务 POST /reverse/runs/{rid}/start
     → ReverseService.startRun() (PENDING → RUNNING)
     → CompletableFuture.runAsync(engineGateway.submit, EXEC)
     → 🆕 ReverseEngineGateway.buildPayload() 组装 4 段
     → 🆕 ReverseEngineGateway.submitToEngine() POST 引擎
     → 引擎 200 ACK 立即返回 (异步)
     → 引擎计算完成 → POST 主服务 /reverse/runs/{rid}/callback
     → 🆕 ReverseService.handleEngineCallback() 写 result + 更新 status
```

**为什么拆服务器**:
- 引擎需要 Python + TensorFlow/PyTorch/CVXPY, 不适合塞进 Java 后端
- 引擎算力需求独立, 可横向扩展
- 主服务与引擎可独立升级/部署

### 4.2 4 段报文组装 SQL (完整可开发)

#### ① 测算方案实体 (`loadScheme`)

```sql
SELECT s.id, s.scheme_code, s.scheme_name, s.scheme_type, s.description,
       s.data_date, s.horizon_months, s.algorithm, s.status, s.model_id, s.coa_scheme_id,
       s.created_by, s.updated_by, s.created_at, s.updated_at,
       m.model_code, m.model_name, m.model_type, m.kpi_scheme_id AS model_kpi_scheme_id,
       cs.scheme_code AS coa_code, cs.scheme_name AS coa_name
  FROM prcp_reverse_scheme s
  LEFT JOIN prcp_model m ON m.id = s.model_id AND m.is_deleted = 0
  LEFT JOIN prcp_coa_scheme cs ON cs.id = s.coa_scheme_id
 WHERE s.id = ? AND s.is_deleted = 0
```

#### ② 目标设置集合 (`loadTargets`)

```sql
SELECT t.id, t.scheme_id, t.kpi_id, t.kpi_code, t.target_name,
       t.target_value, t.constraint_type, t.weight, t.horizon_month, t.sort_order, t.description,
       k.kpi_name AS ref_kpi_name, k.formula AS ref_formula
  FROM prcp_reverse_target t
  LEFT JOIN prcp_kpi_definition k ON k.id = t.kpi_id
 WHERE t.scheme_id = ? AND t.is_deleted = 0
 ORDER BY t.sort_order
```

#### ③ 指标评分方案 (`loadKpiSchemes`)

```sql
-- 步骤 1: 按 model.kpi_scheme_id 查 KpiScheme
SELECT id, scheme_code, scheme_name, description, kpi_count, status, created_at, updated_at
  FROM prcp_kpi_scheme WHERE id = ? AND is_deleted = 0
  -- 找不到回退: WHERE scheme_code = ? (按 algorithm 映射)

-- 步骤 2: 查 score_rule (按 scheme_id + targets 中的 kpi_id)
SELECT id, scheme_id, kpi_id, rule_name, calc_method, total_score, higher_is_better, description, status
  FROM prcp_kpi_score_rule
 WHERE scheme_id = ? AND is_deleted = 0 AND kpi_id IN (?, ?, ?, ?)

-- 步骤 3: 查 segments (PIECEWISE) 或 anchors (LINEAR, x=min_value)
SELECT id, rule_id, seg_order, min_value, max_value, score, segment_desc
  FROM prcp_kpi_score_segment WHERE rule_id = ? AND is_deleted = 0 ORDER BY seg_order
```

#### ④ 指标计量参数 (`loadKpiParams`)

```sql
-- 6 张表相同模式
SELECT * FROM prcp_cet1_param WHERE data_date = ? AND scheme_code = ? AND is_deleted = 0
SELECT * FROM prcp_lcr_param  WHERE data_date = ? AND scheme_code = ? AND is_deleted = 0
SELECT * FROM prcp_nim_param  WHERE data_date = ? AND scheme_code = ? AND is_deleted = 0
SELECT * FROM prcp_nsfr_param WHERE data_date = ? AND scheme_code = ? AND is_deleted = 0
SELECT * FROM prcp_roe_param  WHERE data_date = ? AND scheme_code = ? AND is_deleted = 0

```

### 4.4 报文大小估算

- 6 张参数补录表 × 30 行 ≈ 78 KB (原始)
- gzip 压缩后 ≈ 12 KB
- 即便 6 表 × 200 行 + level≤4 节点, gzip 后 < 200 KB

## 六、关键设计决策

### 6.1 🆕 引擎拆服务器 (HTTP + 异步回调)

**理由**:
- 引擎需要 Python + TensorFlow/PyTorch/CVXPY, 与 Java 后端解耦
- 引擎算力可独立横向扩展
- 主服务故障不影响引擎任务进行中
- 失败兜底: 引擎连接失败时, run 立即标 FAILED + 写 error_message

### 6.2 🆕 ReverseEngineGateway 单类封装

**理由**:
- 报文组装 + HTTP 提交 强耦合, 放一个类便于维护
- 改字段时不用跨文件同步
- 私有助手方法 4 段加载独立可测

### 6.3 🆕 4 段报文结构 (按截图)

**严格按业务截图分 4 段** (详见 `docs/api/reverse-engine-api.md § 〇`):
- ① scheme: 测算方案实体 (1 条)
- ② targets: 目标设置集合 (N 条, 按 scheme_code)
- ③ kpi_schemes: 指标评分方案集合 (按 model.kpi_scheme_id 关联)
- ④ kpi_params: 6 张参数补录表 (按 scheme.data_date)

### 6.4 引擎受理 ACK 立即返回 (异步)

```java
// ReverseService.startRun()
CompletableFuture.runAsync(() -> {
    Map<String, Object> ack = engineGateway.submit(rid, schemeId);
    writeLog(rid, "INFO", "引擎已受理: engine_run_id=" + ack.get("engine_run_id"), 5);
}, EXEC);
```

**理由**: 防止 HTTP 同步等待引擎 5-10 分钟超时

### 6.5 状态机 (PENDING → RUNNING → SUCCESS/FAILED/CANCELLED)

```
PENDING ──start──> RUNNING ──callback SUCCESS──> SUCCESS
                       │                            │
                       ├──callback FAILED──> FAILED
                       │                            │
                       ├──callback CANCELLED──> CANCELLED
                       │
                       └──timeout──> FAILED
```

### 6.6 删除策略 (run → result 硬删, log 永久保留)

```java
// ReverseService.deleteRun()
jdbc.update("UPDATE prcp_reverse_run SET is_deleted=1 WHERE id=?", rid);
jdbc.update("DELETE FROM prcp_reverse_result WHERE run_id=?", rid);
// prcp_reverse_run_log 不删 (永久保留审计)
```
