### 3.2 评分计算 (scoreCalc) 协议

#### 请求

`POST /kpi/score-calc`
```json
{
  "rule_id": 102,
  "value": 118.5
}
```

#### 响应 (PIECEWISE 命中)

```json
{
  "code": 0,
  "data": {
    "rule_id": 101,
    "value": 138.12,
    "score": 70.00,
    "matched": true,
    "higher_is_better": 1,
    "calc_method": "PIECEWISE",
    "matched_segment": {
      "id": 3, "seg_order": 3,
      "min_value": 130.0, "max_value": 150.0, "score": 70.0,
      "segment_desc": "良好（130%-150%）"
    },
    "total_score": 100.00
  }
}
```

#### 响应 (LINEAR 插值)

```json
{
  "code": 0,
  "data": {
    "rule_id": 102,
    "value": 118.5,
    "score": 61.54,
    "matched": true,
    "higher_is_better": 1,
    "calc_method": "LINEAR",
    "matched_range": { "x1": 110.0, "y1": 30.0, "x2": 120.0, "y2": 70.0 },
    "anchor_count": 5,
    "total_score": 100.00
  }
}
```

> `matched_range` 用于前端可视化绘制插值曲线 (ECharts line chart)。

#### 5 步 LINEAR 算法 (KpiService.scoreCalcLinear)

```
输入: segs = [KpiScoreSegment, ...] (按 seg_order 升序), value, rule
输出: 评分 (BigDecimal, 4 位小数)

1. 提取锚点: anchors = [(s.min_value, s.score) for s in segs if s.min_value is not None]
   按 x 升序排列

2. value <= first_anchor.x:
     return clamp_to_first_y      # 下钳位

3. value >= last_anchor.x:
     return clamp_to_last_y       # 上钳位

4. 找到 x1 <= value < x2 的相邻锚点对:
     ratio = (value - x1) / (x2 - x1)
     y = y1 + ratio * (y2 - y1)
     return round(y, 4, HALF_UP)  # 4 位小数

5. 封装 matched_range = {x1, y1, x2, y2}, anchor_count = len(anchors)
```

#### 4 步 PIECEWISE 算法 (KpiService.scoreCalcPiecewise)

```
输入: segs = [KpiScoreSegment, ...] (按 seg_order 升序), value
输出: 评分 (BigDecimal)

1. for seg in segs:
     in_range = true
     if seg.min_value is not None and value < seg.min_value: in_range = false
     if seg.max_value is not None and value > seg.max_value: in_range = false
     if in_range: return seg.score  # 取第一个命中段

2. 所有段都不匹配 → score = null, matched = false (前端提示)
```

## 五、关键设计决策

### 5.1 评分算法支持 **PIECEWISE + LINEAR** (双模式)

**理由**:
- **PIECEWISE 分段**: 业务人员易理解 (哪个区间多少分), 适合阶梯型指标 (LCR ≥150% 满分)
- **LINEAR 线性插值**: 适合连续型指标 (ROE 在 8-12% 范围内精细评分), 减少段数

**实现**:
- `prcp_kpi_score_rule.calc_method` 区分算法
- 锚点复用 `prcp_kpi_score_segment` 表 (x=min_value, y=score)
- 5 步 LINEAR 算法 + 4 步 PIECEWISE 算法 (KpiService 私有方法)
- 前端按 calc_method 动态切换 Modal 表格列

### 5.2 scoreCalc 响应 **统一包装**

**返回结构** (PIECEWISE / LINEAR 通用字段):
```json
{
  "rule_id": 102, "value": 118.5, "score": 61.54, "matched": true,
  "higher_is_better": 1, "calc_method": "LINEAR", "total_score": 100.00
}
```

**算法特有字段**:
- PIECEWISE: `matched_segment` (段详情)
- LINEAR: `matched_range {x1,y1,x2,y2}` + `anchor_count`

**理由**: 前后端可通用处理, 不必按 method 区分响应解析。

### 5.3 prcp_model 关联 kpi_scheme_id (跨模块)

`prcp_model.kpi_scheme_id` 直接关联 `prcp_kpi_scheme.id`
**理由**:
- 测算方案 (reverse) 选模型时, 自动带出关联的 KPI 评分方案
- 反算引擎调用时, 直接通过 model.kpi_scheme_id 找到 score_rule

### 5.4 软删除统一

所有表 `is_deleted=0/1`, MyBatis-Plus `LogicDelete` 自动注入
- 列表查询自动 `WHERE is_deleted=0`
- 删除时 `UPDATE ... SET is_deleted=1`
- 关联查询 (e.g. 评分段) 需手动加 `is_deleted=0` 条件
