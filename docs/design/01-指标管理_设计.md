# 指标管理（KPI）— 设计方案

| 版本 | 日期 | 作者 |
|---|---|---|
| v1.0 | 2026-10-08 | 主程 |

## 一、整体架构

```
前端 Vue3 (src/views/kpi/Index.vue)
   ↓ axios (request baseURL: /prcp-java/api)
后端 Spring Boot (prcp-business/com/prcp/business/kpi/)
   ├── controller/KpiController.java
   ├── service/KpiService.java
   ├── entity/{KpiScheme, KpiDefinition, KpiScoreRule, KpiScoreSegment, KpiValue}.java
   └── mapper/{KpiMapper, KpiValueMapper, KpiScoreRuleMapper, KpiScoreSegmentMapper}.java
   ↓ MyBatis-Plus + Druid
MySQL 8.0 prcp_db
   └── 5 张表: prcp_kpi_scheme / prcp_kpi_definition / prcp_kpi_value
                / prcp_kpi_score_rule / prcp_kpi_score_segment
```

## 二、数据库设计

### 2.1 ER 关系

```
prcp_kpi_scheme (1) ──┬── (N) prcp_kpi_definition
                      │              │
                      │              └── (1) ─── (N) prcp_kpi_score_rule
                      │                                   │
                      │                                   └── (1) ── (N) prcp_kpi_score_segment
                      │
                      └── (N) prcp_kpi_value
                                  │
                                  └── (N) prcp_kpi_definition (kpi_id 外键)
```

#### prcp_kpi_scheme（指标方案）
| 字段 | 类型 | 备注 |

| 字段 | 类型 | 备注 |

### 3.2 试算协议

`POST /kpi/recalc?kpi_id=5&data_date=2025-12-31`

请求：`kpi_id` + `data_date`
响应：
```json
{
  "code": 0,
  "data": {
    "kpi_id": 5,
    "kpi_code": "REG_ROE",
    "data_date": "2025-12-31",
    "current_value": 11.66,
    "score": 70,
    "duration_ms": 38
  }
}
```

### 3.1 公式占位符

公式支持以下占位符（解析时替换为 prcp_data_basic 同日期的对应字段）：
- `${balance_x}` → 原余额（orig_m1）
- `${rate_begin}` → period 起始利率（begin_rate）
- `${delta_eve}` → 经济价值变动
- `${asset_total}` / `${liability_total}` / `${equity_total}` → 资产/负债/权益总和

## 五、关键设计决策

### 5.1 评分规则用 **5 段 PIECEWISE**（而非折线/连续函数）

**理由**：
- 业务人员易理解（哪个区间多少分）
- 落库简单（5 行数据即可）
- 性能（线性扫描 5 段，比解析公式快）

### 5.2 试算用 **JS 表达式引擎**（Nashorn / 自研）

**理由**：
- 避免引入 Python 依赖
- 沙箱安全（限制只能用 Math/基础运算符）
- 解析快（AST 编译 + 缓存）

### 5.3 value 表**同时支持试算和手动**（同一行通过 calc_source 区分）

**理由**：
- 公式自动算大多数 + 少量手工修正
- 历史可比对（看 MANUAL vs FORMULA 占比）

## 六、与其他模块的关系

- **prcp_data_basic**：试算数据源（orig_m1/begin_rate 等）
- **prcp_data_reverse**：组合反算结果（被 prcp_metric_coefficient 关联）
- **prcp_rpt_item**：KPI 关联的报表项（间接：rpt_id）
- **Reverse / Dashboard**：`prcp_kpi_value` 是 KPI 雷达图的评分源
